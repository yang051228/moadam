# 모아담 · 기숙사 공동구매 MVP

한 사람이 한 단위만 필요한 생필품을 같은 기숙사의 학생들과 나누는 한국어 웹앱입니다. 학생은 내 분담금과 수령 장소를 확인하고 참여합니다. 개설자는 모집 결과를 확인한 뒤 판매처에서 주문하고, 소분과 전달을 기록합니다.

## 실행

Node.js 24 LTS와 npm이 필요합니다. 압축을 풀고 package.json이 있는 폴더에서 실행합니다.

```sh
npm ci
npm run dev
```

브라우저에서 **http://localhost:3000**을 엽니다. 별도 API 키 없이 시작합니다. 서버가 첫 DB 접근 시 마이그레이션을 적용합니다. 기본 데이터 파일은 `data/dorm.sqlite`입니다. 저장 위치를 바꾸려면 `.env.example`을 `.env.local`로 복사해 `DORM_DB`를 지정하세요.

```sh
npm run build
npm start
```

같은 서버에 접속하는 기기끼리 가입 계정으로 공구를 공유할 수 있습니다. 각자 로컬 서버를 실행하면 서로 다른 DB를 사용합니다. 단일 Node 서버와 영구 볼륨을 전제로 합니다.

## 바로 체험하기

1. 홈에서 **도톰한 3겹 데일리 화장지**를 선택합니다. **데모 체험 → 일반 참여자 → A기숙사**로 입장합니다.
2. 새 데모 공간에서는 6단위 중 5단위가 신청되어 있습니다. 마지막 **5개·3,150원**을 확인하고 참여하면 모집 완료로 바뀝니다.
3. **마이페이지 → 계정 전환 → 운영자**를 선택하고 같은 기숙사에서 해당 공구를 엽니다. 구매 확정 검토 → 판매처 주문 완료 기록 → 배송 시작 순으로 진행합니다.
4. 분배 준비 5항목을 확인하고 수령 가능 안내를 보냅니다. 참여자 계정에서 수령 확인 후 개설자가 전달을 확인합니다. 기존 시드 참여자도 계정 선택기의 학생 목록에서 전환할 수 있습니다.
5. 짧게 종주하려면 학생 공구를 **모집 단위 1, 총 수량 1**로 개설하세요. 다른 데모 계정 한 명이 참여하고 양측의 수령 확인을 마치면 공구를 종료할 수 있습니다.

데모 공간은 브라우저별로 독립되어 있습니다. 쿠키를 보존하면 역할을 바꿔도 같은 데이터를 사용합니다. **다른 브라우저의 학생과 테스트할 때는 두 브라우저에서 각각 회원가입**하고 같은 기숙사를 선택하세요. 가입 계정은 공유 캠퍼스로 입장합니다. 공유 캠퍼스는 빈 목록으로 시작합니다. 공구를 하나 개설하고 상세의 링크를 전달하면 같은 기숙사 계정으로 참여할 수 있습니다.

대화와 상세는 8초, 홈 알림은 18초 간격으로 갱신합니다. 사용자가 수행한 작업은 성공 응답 후 즉시 다시 조회합니다. 인앱 알림은 가입 또는 데모 입장 시 선택합니다. 수령 일정 변경은 공구 전체에 공지하고 개별 재수령 조율 결과는 요청자에게 전달합니다.

### 실패와 예외

- **모집 실패** — 마감 시 목표 미달이거나 개설자가 미달 상태에서 조기 마감하면 신규 참여를 닫고 모의 결제를 취소합니다. 기존 상품 조건을 복사해 새 일정으로 다시 열 수 있습니다.
- **주문 전 취소** — 신청을 비활성화하고 모집 수량과 분담금을 재계산합니다. 마감까지 시간이 남으면 모집을 다시 엽니다.
- **주문 후 취소** — 검토 요청으로 접수합니다. 개설자 또는 운영자가 승인·반려하고 결과를 남깁니다. 승인 시 해당 건의 모의 결제를 취소하고, 이미 주문한 다른 참여자의 분담금은 유지합니다.
- **주문 지연** — 예정일이 지나면 개설자, 하루 더 지나면 담당 운영자에게 알립니다. 운영자는 진행을 중단할 수 있습니다.
- **미수령·파손·누락** — 참여자는 사진과 사유를 제출하거나 재수령을 요청합니다. 담당자가 일정을 답하거나 변경합니다. 운영자는 해결 내용과 함께 미수령 분쟁을 종결할 수 있습니다.
- **공구 종료** — 활성 참여자 전원의 수령·전달 확인과 미처리 문제·취소 요청 해소 후 개설자 또는 운영자가 종료합니다.

마감과 지연 감지는 앱 요청 시 실행됩니다. 앱이 닫힌 시간에도 처리하려면 같은 서버에서 `npm run sweep`을 주기적으로 호출하세요. 이 명령은 여러 번 실행해도 기한 알림을 중복 생성하지 않습니다. 외부 스케줄러는 연결하지 않았습니다.

**정산**은 서버에서 계산합니다. 상품 수량을 모집 단위 수로 정확히 나눌 수 있어야 합니다. 신청 순으로 누적 단위까지의 금액을 원 단위로 내림하고 직전 누적 금액을 빼서 개인 부담금을 정합니다. 목표 수량이 차면 분담금의 합이 상품 총가격과 일치합니다. 10,001원을 두 사람에게 균등 분배하면 5,000원과 5,001원입니다.

**동시성**은 SQLite의 `BEGIN IMMEDIATE` 트랜잭션으로 처리합니다. 최신 상태에서 잔여 수량을 읽고 신청·모의 결제·재계산·상태 변경을 함께 커밋합니다. 활성 신청에는 공구와 사용자 조합의 고유 인덱스가 있습니다.

**일반 학생**은 같은 공간·기숙사의 공구만 조회하고 참여합니다. **개설자**는 자기 공구의 참여·분배·요청을 관리합니다. **운영자**는 자기 공간의 기숙사를 관리합니다. 공구 대화는 개설자와 활성 참여자에게만 열립니다. 서버는 클라이언트가 보낸 역할이나 사용자 ID를 권한의 근거로 사용하지 않습니다. 개발용 운영자 계정은 전용 데모 공간에 한정됩니다. 공유 캠퍼스 운영자 지정은 서버 콘솔에서 `npm run operator -- 가입아이디`로 수행합니다.

## 검증

```sh
npm test
npm run typecheck
npm run build
npx playwright install chromium
npm run e2e
```

DB 테스트는 임시 DB에서 실행합니다. 일반 참여와 수령, 학생 개설, 마감 실패, 주문 전후 취소, 미수령 재조율 등 요청한 다섯 시나리오에 더해 타 기숙사 접근, 대화 권한, 주문 지연, 첨부·분쟁 처리, 회원 세션과 공간 격리를 확인합니다. 별도 Node 프로세스 두 개가 마지막 한 단위에 동시에 신청해 한 건만 성공하는 경합 테스트를 포함합니다.

브라우저 테스트 파일은 390px 참여·취소, 데스크톱 개설과 독립 세션 간 동시 신청, 비로그인 API 차단을 다룹니다. 구현 환경에서 독립 Playwright Chromium 프로세스의 소켓 생성이 제한되어 전체 E2E 스위트는 통과 확인하지 못했습니다. 별도로 제공된 브라우저에서 데스크톱 홈·탐색과 390px 화면의 데모 입장 → 5개·3,150원 확인 → 참여 → 취소 → 재모집을 조작해 확인했습니다.
